# Хамелеон — натяжные потолки

Современный адаптивный сайт для компании по производству и установке натяжных потолков в Ростове-на-Дону.

Проект представляет собой редизайн сайта компании «Хамелеон» с упором на современный интерфейс, адаптивность, производительность, базовую техническую SEO-оптимизацию и получение заявок через сайт.

## О проекте

Сайт разработан как коммерческий проект для компании, занимающейся производством и установкой натяжных потолков.

Основные задачи проекта:

* обновить визуальный стиль сайта;
* создать современный адаптивный интерфейс;
* удобно представить услуги, акции, цены и выполненные проекты;
* реализовать интерактивный калькулятор стоимости;
* организовать получение заявок с сайта и контроль их обработки;
* интегрировать формы и онлайн-чат с Telegram через серверный обработчик;
* дать администратору возможность менять акции и цены без программиста;
* оптимизировать изображения и загрузку страниц;
* выполнить базовую техническую SEO-оптимизацию;
* подготовить проект к production deployment.

## Функциональность

### Главный экран

Адаптивный Hero-блок с основным предложением компании, преимуществами и формой заявки на бесплатный замер.

Форма собирает имя и номер телефона пользователя и отправляет заявку через API.

### Калькулятор стоимости

Интерактивный калькулятор позволяет указать:

* ширину и длину помещения;
* тип потолка;
* количество углов;
* количество светильников.

На основе выбранных параметров рассчитывается предварительная стоимость. Типы потолка и цены задаются в панели администратора.

После расчёта пользователь может перейти к форме бесплатного замера. Результаты калькулятора передаются вместе с контактными данными пользователя при отправке заявки.

### Акции

Отдельный раздел с актуальными предложениями компании. Список акций, их тексты и порядок задаются в панели администратора.

При выборе акции в браузере сохраняется её идентификатор, после чего пользователь переходит к форме бесплатного замера. При отправке формы имя, номер телефона и идентификатор акции передаются одним запросом на сервер.

### Преимущества

Раздел с основными преимуществами компании:

* качественные материалы;
* собственное производство;
* собственные монтажные бригады;
* контроль качества;
* короткие сроки;
* гарантия;
* безналичная оплата;
* рассрочка.

### Портфолио

Галерея выполненных работ компании.

Изображения оптимизированы для веба и переведены в формат WebP для уменьшения размера загружаемых ресурсов.

### Прайс

Карточки с основными вариантами натяжных потолков и ориентировочной стоимостью. Тексты и цены карточек меняются в панели администратора, фотографии — в коде.

### Производство

Раздел с информацией о собственном производстве и особенностях работы компании.

### Партнёры

Блок с партнёрами компании и бонусной программой.

### Команда

Раздел с информацией о специалистах компании.

### Заявки

На сайте реализованы формы для получения заявок:

* форма на главном экране;
* форма бесплатного замера.

Дополнительно к заявке могут передаваться:

* параметры, выбранные пользователем в калькуляторе стоимости;
* информация о выбранной акции.

Frontend отправляет данные на относительный API-адрес:

```text
/api/leads
```

Использование относительного адреса позволяет не привязывать frontend к локальному адресу backend.

Серверный обработчик сохраняет заявку в базу данных и передаёт уведомление менеджерам в Telegram с кнопкой «✋ Беру».

### Онлайн-чат

Кнопка 💬 в правом нижнем углу открывает чат с менеджером. Сообщения посетителя приходят менеджерам в Telegram; ответ (Reply) на такое сообщение в Telegram или ответ из панели появляется у посетителя на сайте. Переписка сохраняется в базе данных.

### Панель заявок

Веб-панель для сотрудников по адресу `/api/admin/` (вход по логину и паролю).

Менеджер:

* видит все заявки и чаты, фильтрует заявки по статусу и «только мои»;
* берёт заявку в работу (в панели или кнопкой «Беру» в Telegram);
* меняет статус: «Новая», «В работе», «Выполнена», «Отказ»;
* оставляет комментарии — в панели или ответом (Reply) на заявку в Telegram;
* видит историю заявки: когда получена, кто и когда взял, что ответил;
* отвечает посетителям в чате.

Панель обновляется каждые 5 секунд, показывает счётчики новых заявок и ожидающих чатов, подаёт звуковой сигнал и уведомление браузера.

Администратор дополнительно:

* создаёт и отключает пользователей, сбрасывает пароли, назначает роли;
* привязывает Telegram ID сотрудника (сотрудник узнаёт его командой `/myid` у бота);
* переназначает заявки;
* редактирует акции, цены калькулятора и карточки прайса (вкладка «Акции и цены»).

## Обработка персональных данных

В формах, собирающих имя и номер телефона, предусмотрено согласие пользователя на обработку персональных данных.

На сайте размещена отдельная страница политики обработки персональных данных:

```text
/privacy.html
```

Ссылка на политику доступна в формах, онлайн-чате и Footer.

Заявки и переписка хранятся в базе данных на сервере; доступ к ним есть только у сотрудников по личному логину и паролю.

## Архитектура

Основная схема обработки заявки:

```text
Сайт (React / Vite)                 Сотрудники
   │  POST /api/leads                  │ панель /api/admin/
   │  /api/chat/...                    │
   │  GET /api/site/settings           │
   ▼                                   ▼
FastAPI (backend/) ──── SQLite: заявки, история, чаты, пользователи, настройки
   │       ▲
   │       │ нажатия «Беру» и ответы (long polling getUpdates)
   ▼       │
Telegram Bot API ──► чаты менеджеров
```

Обработчик в production — FastAPI из папки `backend/`. Других реализаций API в проекте нет.

| Файл | Назначение |
|---|---|
| `main.py` | приложение, приём заявок `/api/leads`, защита от спама, настройки для сайта |
| `db.py` | база данных SQLite и её схема |
| `crm.py` | заявки, история, чаты |
| `auth.py` | пароли, сессии, роли, защита от подбора пароля |
| `admin_api.py` | API панели `/api/admin/...` |
| `chat_api.py` | онлайн-чат для посетителей `/api/chat/...` |
| `telegram_bot.py` | уведомления, кнопка «Беру», приём ответов из Telegram |
| `site_settings.py` | акции, цены калькулятора и прайса (значения по умолчанию) |
| `panel/index.html` | веб-панель (одна страница без сборки) |
| `manage.py` | служебные команды (создание администратора) |
| `smoke_test.py` | автотест API |

### Контракт `/api/leads`

* `name`, `phone` — обязательны; телефон должен содержать 10–11 цифр;
* `source` — одно из значений `contact`, `calculator`, `promotion`, `hero_discount`;
* `promotion_id` — идентификатор акции. Название, выгоду и текст акции сервер берёт из настроек сайта, неизвестный ID отклоняется;
* `calculator` — только исходные параметры (ширина, длина, тип полотна, углы, светильники). Площадь и стоимость сервер пересчитывает сам по ценам из настроек;
* лишние поля и значения вне допустимых диапазонов отклоняются с кодом `422`.

### Настройки сайта

Акции, цены калькулятора и тексты карточек прайса хранятся в базе данных и меняются администратором в панели. Сайт загружает их с `/api/site/settings`. Если сервер недоступен, сайт показывает значения по умолчанию из `src/siteSettings.js`; они должны совпадать с `DEFAULTS` в `backend/site_settings.py`.

### Защита

* скрытое поле-ловушка в формах и чате;
* проверка минимального времени заполнения формы;
* ограничение частоты заявок и сообщений чата с одного адреса и в целом по сайту (ответ `429`);
* панель: пароли хранятся в виде хэша scrypt, cookie сессии `HttpOnly`/`Secure`/`SameSite=Strict`, CSRF-токен для изменяющих запросов, блокировка входа на 15 минут после 5 неверных паролей;
* всё, что присылают посетители, выводится в панели только с экранированием;
* служебная документация FastAPI (`/docs`, `/openapi.json`) отключена.

Для корректного подсчёта по адресам прокси-сервер должен передавать реальный IP посетителя (`X-Real-IP` / `X-Forwarded-For`).

### Журналы

В журнал API не записываются имя, телефон, токен бота и chat ID. Для поиска заявки используется `request_id` и номер заявки. Запросы библиотеки httpx не журналируются: в их адресах содержится токен бота.

## SEO и производительность

В проекте выполнена базовая техническая SEO-оптимизация:

* настроен язык документа;
* добавлен SEO `title`;
* добавлен `meta description`;
* добавлен `robots` meta tag;
* добавлены базовые Open Graph meta tags;
* используется семантическая структура заголовков;
* основной поисковый запрос используется в `h1`;
* изображения оптимизированы и переведены в WebP;
* для изображений вне первого экрана используется lazy loading;
* подготовлен базовый `robots.txt`;
* проверен production build.

Финальная SEO-конфигурация зависит от production-домена.

После получения и подключения домена необходимо будет добавить:

* canonical URL;
* `og:url`;
* `og:image`;
* `sitemap.xml`;
* адрес sitemap в `robots.txt`;
* production URL сайта в необходимых метаданных;
* подключение сайта к сервисам для вебмастеров.

### robots.txt

Сейчас используется минимальный вариант:

```text
User-agent: *
Allow: /
```

Полный `robots.txt` будет настроен после получения production-домена и создания `sitemap.xml`.

## Локальный запуск

### Frontend

Установить зависимости:

```bash
npm ci
```

Запустить development server:

```bash
npm run dev
```

Создать production build:

```bash
npm run build
```

После успешной сборки готовые статические файлы будут находиться в директории:

```text
dist/
```

Локально проверить production build:

```bash
npm run preview
```

### FastAPI backend

Перейти в директорию backend:

```bash
cd backend
```

Создать виртуальное окружение:

```bash
python3 -m venv venv
```

Для Windows:

```bash
venv\Scripts\activate
```

Для Linux/macOS:

```bash
source venv/bin/activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Создать файл `backend/.env` и указать переменные окружения:

```env
TELEGRAM_BOT_TOKEN=your_telegram_bot_token
TELEGRAM_CHAT_IDS=chat_id_1,chat_id_2
# Только для локальной разработки:
CORS_ORIGINS=http://localhost:5173
HAMELEON_COOKIE_SECURE=0
```

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHAT_IDS` | чаты менеджеров через запятую: сюда приходят заявки и сообщения чата |
| `HAMELEON_DB` | путь к файлу базы данных (по умолчанию `backend/data/hameleon.db`); в production база хранится вне папки репозитория |
| `HAMELEON_TELEGRAM_POLLING` | `0` — не получать нажатия и ответы из Telegram (для тестового экземпляра: опрашивать бота может только один процесс) |
| `HAMELEON_COOKIE_SECURE` | `0` — разрешить вход в панель по HTTP (только локально) |
| `CORS_ORIGINS` | разрешённые адреса frontend для локальной разработки; в production не задаётся |

Файл `.env` содержит секретные данные и не должен добавляться в Git. В production переменные задаются в конфигурации сервера.

Запустить API из директории `backend`:

```bash
uvicorn main:app --reload
```

По умолчанию API запускается на порту `8000`. При первом запуске создаётся база данных.

Создать первого администратора (пароль будет запрошен без вывода на экран):

```bash
python manage.py create-admin admin "Имя Фамилия"
```

Остальных пользователей администратор создаёт в панели.

### Проверка backend

```bash
python smoke_test.py
```

Тест запускает API с временной базой без Telegram и проверяет заявки, вход, роли, «взять в работу», комментарии, настройки сайта и чат.

## Сборка

Для создания frontend-сборки выполнить из корневой директории проекта:

```bash
npm ci
npm run build
```

`npm ci` устанавливает зависимости строго по `package-lock.json`, поэтому сборка воспроизводима. `npm install` используется только при добавлении или обновлении зависимостей.

Готовая сборка создаётся в директории `dist/`. Проверить её локально:

```bash
npm run preview
```

## Проверки

При каждом push в любую ветку и в pull request GitHub Actions (`.github/workflows/ci.yml`) выполняет:

* `npm ci`, `npm run lint`, `npm run build`;
* установку зависимостей backend, проверку синтаксиса и `backend/smoke_test.py`.

Крупные изменения удобно сначала отправить в отдельную ветку: она проверяется, но не попадает на сайт.

После выкладки рекомендуется вручную проверить:

* заявку с главного экрана, на бесплатный замер, из калькулятора (стоимость в Telegram совпадает с сайтом) и с выбранной акцией;
* кнопку «Беру» и ответ (Reply) на заявку в Telegram;
* онлайн-чат: сообщение с сайта и ответ из Telegram и из панели.

## Безопасность

В Git-репозиторий не должны попадать:

* `.env`;
* конфигурационные файлы с секретами;
* Telegram Bot Token;
* Telegram Chat ID;
* API-ключи и пароли;
* резервные копии и приватные ключи.

Frontend не содержит Telegram Bot Token или Chat ID. Значения переменных `VITE_*` попадают в браузер, поэтому секреты в них хранить нельзя.

## Production deployment

Сервер автоматически проверяет ветку `main` и выкладывает новые коммиты. Поэтому любой push в `main` попадает на сайт: перед отправкой изменений убедитесь, что проверки GitHub Actions проходят.

Требования к серверу:

* веб-сервер передаёт API все адреса `/api/...` (заявки, панель, чат, настройки сайта) вместе с реальным IP посетителя;
* в папке репозитория на сервере не должно появляться посторонних файлов: скрипт обновления останавливается при локальных изменениях (временные файлы Python отключены через `PYTHONDONTWRITEBYTECODE=1`, база вынесена через `HAMELEON_DB`);
* файл базы данных нужно регулярно копировать в резервную копию: в нём все заявки, переписка и пользователи панели.

Секреты, адреса серверов и команды администрирования в репозитории не описываются и хранятся отдельно.
