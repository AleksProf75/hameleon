# Хамелеон — натяжные потолки

Современный адаптивный сайт для компании по производству и установке натяжных потолков в Ростове-на-Дону.

Проект представляет собой редизайн сайта компании «Хамелеон» с упором на современный интерфейс, адаптивность, производительность, базовую техническую SEO-оптимизацию и получение заявок через сайт.

## О проекте

Сайт разработан как коммерческий проект для компании, занимающейся производством и установкой натяжных потолков.

Основные задачи проекта:

* обновить визуальный стиль сайта;
* создать современный адаптивный интерфейс;
* удобно представить услуги, акции, цены и выполненные проекты;
* реализовать интерактивный калькулятор стоимости;
* организовать получение заявок с сайта;
* интегрировать формы с Telegram через серверный обработчик;
* оптимизировать изображения и загрузку страниц;
* выполнить базовую техническую SEO-оптимизацию;
* подготовить проект к production deployment.

## Функциональность

### Главный экран

Адаптивный Hero-блок с основным предложением компании, преимуществами и формой заявки на бесплатный замер.

Форма собирает имя и номер телефона пользователя и отправляет заявку через API.

### Калькулятор стоимости

Интерактивный калькулятор позволяет указать:

* ширину и длину помещения;
* тип потолка;
* количество углов;
* количество светильников.

На основе выбранных параметров рассчитывается предварительная стоимость.

После расчёта пользователь может перейти к форме бесплатного замера. Результаты калькулятора передаются вместе с контактными данными пользователя при отправке заявки.

### Акции

Отдельный раздел с актуальными предложениями компании.

При выборе акции информация о ней сохраняется, после чего пользователь переходит к форме бесплатного замера.

При отправке формы имя, номер телефона и информация о выбранной акции передаются одним запросом на сервер.

### Преимущества

Раздел с основными преимуществами компании:

* качественные материалы;
* собственное производство;
* собственные монтажные бригады;
* контроль качества;
* короткие сроки;
* гарантия;
* безналичная оплата;
* рассрочка.

### Портфолио

Галерея выполненных работ компании.

Изображения оптимизированы для веба и переведены в формат WebP для уменьшения размера загружаемых ресурсов.

### Прайс

Карточки с основными вариантами натяжных потолков и ориентировочной стоимостью.

### Производство

Раздел с информацией о собственном производстве и особенностях работы компании.

### Партнёры

Блок с партнёрами компании и бонусной программой.

### Команда

Раздел с информацией о специалистах компании.

### Заявки

На сайте реализованы формы для получения заявок:

* форма на главном экране;
* форма бесплатного замера.

Дополнительно к заявке могут передаваться:

* параметры, выбранные пользователем в калькуляторе стоимости;
* информация о выбранной акции.

Frontend отправляет данные на относительный API-адрес:

```text
/api/leads
```

Использование относительного адреса позволяет не привязывать frontend к локальному адресу backend.

Серверный обработчик принимает данные заявки и передаёт уведомление в Telegram через Telegram Bot API.

## Обработка персональных данных

В формах, собирающих имя и номер телефона, предусмотрено согласие пользователя на обработку персональных данных.

На сайте размещена отдельная страница политики обработки персональных данных:

```text
/privacy.html
```

Ссылка на политику доступна в формах и Footer.

## Архитектура

Основная схема обработки заявки:

```text
React / Vite
      │
      │ POST /api/leads
      │ HTTP / JSON
      ▼
Server API Handler
      │
      ▼
Telegram Bot API
      │
      ▼
Telegram
```

Секретные данные, необходимые для работы Telegram Bot API, должны храниться только на серверной стороне и не должны передаваться во frontend или публиковаться в Git-репозитории.

В проекте также присутствует локальный FastAPI backend, использовавшийся для разработки и тестирования API.

Production-обработчик API будет добавлен в репозиторий отдельно без секретных данных.

## SEO и производительность

В проекте выполнена базовая техническая SEO-оптимизация:

* настроен язык документа;
* добавлен SEO `title`;
* добавлен `meta description`;
* добавлен `robots` meta tag;
* добавлены базовые Open Graph meta tags;
* используется семантическая структура заголовков;
* основной поисковый запрос используется в `h1`;
* изображения оптимизированы и переведены в WebP;
* для изображений вне первого экрана используется lazy loading;
* подготовлен базовый `robots.txt`;
* проверен production build.

Финальная SEO-конфигурация зависит от production-домена.

После получения и подключения домена необходимо будет добавить:

* canonical URL;
* `og:url`;
* `og:image`;
* `sitemap.xml`;
* адрес sitemap в `robots.txt`;
* production URL сайта в необходимых метаданных;
* подключение сайта к сервисам для вебмастеров.

### robots.txt

Сейчас используется минимальный вариант:

```text
User-agent: *
Allow: /
```

Полный `robots.txt` будет настроен после получения production-домена и создания `sitemap.xml`.

## Локальный запуск

### Frontend

Установить зависимости:

```bash
npm install
```

Запустить development server:

```bash
npm run dev
```

Создать production build:

```bash
npm run build
```

После успешной сборки готовые статические файлы будут находиться в директории:

```text
dist/
```

Локально проверить production build:

```bash
npm run preview
```

### Локальный FastAPI backend

В проекте присутствует FastAPI backend, который может использоваться для локальной разработки и тестирования API.

Перейти в директорию backend:

```bash
cd backend
```

Создать виртуальное окружение:

```bash
python3 -m venv venv
```

Для Windows:

```bash
venv\Scripts\activate
```

Для Linux/macOS:

```bash
source venv/bin/activate
```

Установить зависимости:

```bash
pip install fastapi "uvicorn[standard]" python-dotenv httpx
```

Создать файл:

```text
backend/.env
```

Добавить необходимые переменные окружения:

```env
TELEGRAM_BOT_TOKEN=your_telegram_bot_token
TELEGRAM_CHAT_ID=your_telegram_chat_id
```

Файл `.env` содержит секретные данные и не должен добавляться в Git.

Запустить API из директории `backend`:

```bash
uvicorn main:app --reload
```

По умолчанию локальный FastAPI backend запускается на порту `8000`.

> В production frontend использует относительный адрес `/api/leads`. Локальный FastAPI backend является отдельным вариантом для разработки и тестирования и не описывает текущую production-конфигурацию сервера.

## Безопасность

Секретные данные backend должны храниться только на серверной стороне.

В Git-репозиторий не должны попадать:

* `.env`;
* production-конфигурационные файлы с секретами;
* Telegram Bot Token;
* Telegram Chat ID;
* API-ключи;
* пароли;
* другие секретные данные.

Frontend не содержит Telegram Bot Token или Chat ID.

Production PHP-обработчик должен быть добавлен в GitHub без реальных секретных данных.

Для него также должен быть добавлен пример конфигурационного файла, содержащий только названия необходимых параметров и тестовые значения-заглушки.

## Production deployment

Frontend подготовлен для работы с серверным API через относительный адрес:

```text
/api/leads
```

Для production-публикации frontend необходимо:

1. Установить зависимости:

```bash
npm install
```

2. Создать production build:

```bash
npm run build
```

3. Разместить содержимое директории `dist` на production-сервере.

4. Разместить production-обработчик API, принимающий запросы по адресу:

```text
/api/leads
```

5. Создать серверную конфигурацию Telegram Bot API на основе файла-примера и указать реальные секретные данные только на сервере.

6. Проверить отправку всех типов заявок:

* заявка с главного экрана;
* заявка на бесплатный замер;
* заявка с результатами калькулятора;
* заявка с выбранной акцией.

7. Проверить, что имя, номер телефона и дополнительные данные заявки корректно передаются серверному обработчику.

8. Настроить HTTPS и production-домен.

9. Выполнить финальную SEO-настройку:

* добавить canonical URL;
* добавить `og:url`;
* добавить `og:image`;
* создать `sitemap.xml`;
* дополнить `robots.txt`;
* подключить сайт к Яндекс Вебмастеру и Google Search Console;
* отправить sitemap на индексацию.

10. Повторно провести Lighthouse-аудит после размещения сайта на production-сервере.

> Точные инструкции по размещению production PHP-обработчика и созданию его конфигурационного файла необходимо дополнить после добавления актуального серверного обработчика в репозиторий.
